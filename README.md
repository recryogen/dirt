# 🔥 Сделать грязь — учебные задания

Сайт для группы студентов: дисциплины, задания к ним и одна главная кнопка
**«СДЕЛАТЬ ГРЯЗЬ»**, которая собирает все ваши невыполненные задания в один список
от самого горящего до самого спокойного.

- Без регистрации и паролей — пользователь определяется по имени/нику (хранится в браузере).
- Данные общие для всех — лежат в облачной базе [Supabase](https://supabase.com).
- Нет своего сервера — сайт целиком статический и публикуется на **GitHub Pages**.
- Стек: React + TypeScript + Vite, обычный CSS.

## 1. Что нужно заранее

- [Node.js](https://nodejs.org) версии **18 или новее** (проверка: `node -v`).
- Аккаунт на [supabase.com](https://supabase.com) (бесплатного тарифа хватает).
- Аккаунт на [github.com](https://github.com) и установленный [Git](https://git-scm.com).

## 2. Установка проекта

Откройте терминал в папке проекта (там, где лежит `package.json`) и установите зависимости:

```bash
npm install
```

Команда скачает React, Vite, TypeScript и клиент Supabase в папку `node_modules`.

## 3. Создание проекта Supabase

1. Зайдите на [supabase.com](https://supabase.com) → **Start your project** → войдите (например, через GitHub).
2. Нажмите **New project**.
3. Заполните:
   - **Name** — любое, например `study-dirt`;
   - **Database Password** — придумайте и сохраните (для сайта он не нужен);
   - **Region** — ближайший к вам (например, Frankfurt).
4. Нажмите **Create new project** и подождите 1–2 минуты, пока проект запустится.

## 4. Создание таблиц

1. В левом меню Supabase откройте **SQL Editor** → **New query**.
2. Откройте в проекте файл [`supabase/schema.sql`](supabase/schema.sql), скопируйте **всё** содержимое и вставьте в редактор.
3. Нажмите **Run**. Должно появиться `Success. No rows returned`.

Скрипт создаёт таблицы `users`, `categories`, `subjects`, `tasks`, `task_completions`,
две категории — «Чето серьезное» и «Хуйня», — и открывает доступ для анонимного ключа.
Запускать его повторно безопасно.

Проверить результат можно в **Table Editor**: там должны появиться пять таблиц,
а в `categories` — две строки.

## 5. Куда вставить Supabase URL и anon key

1. В Supabase откройте **Project Settings** (шестерёнка) → **API**
   (в новых версиях панели — **API Keys / Data API**).
2. Скопируйте:
   - **Project URL** — вида `https://abcdefgh.supabase.co`;
   - **anon public** ключ (длинная строка, начинается с `eyJ...`; в новой панели он может называться *publishable key*).
   Ключ `service_role` / *secret* **не используйте** — он даёт полный доступ и не должен попадать на сайт.
3. В корне проекта скопируйте `.env.example` в `.env`:

   ```bash
   # macOS / Linux / Git Bash
   cp .env.example .env
   # Windows (cmd)
   copy .env.example .env
   ```

4. Откройте `.env` и вставьте свои значения:

   ```env
   VITE_SUPABASE_URL=https://abcdefgh.supabase.co
   VITE_SUPABASE_ANON_KEY=eyJhbGciOi...ваш_ключ...
   ```

Файл `.env` добавлен в `.gitignore` и **не попадёт в GitHub**. В репозитории лежит только `.env.example` с пустыми значениями.

## 6. Запуск локально

```bash
npm run dev
```

Откройте адрес из терминала (обычно <http://localhost:5173>).
Изменения в коде подхватываются автоматически. Остановить сервер — `Ctrl + C`.

> Если поменяли `.env`, перезапустите `npm run dev` — переменные читаются только при старте.

## 7. Сборка проекта

```bash
npm run build
```

Готовый сайт появится в папке `dist/`. Проверить сборку локально:

```bash
npm run preview
```

Команда `build` заодно проверяет типы TypeScript: если в коде есть ошибка, сборка остановится и покажет её.

## 8. Публикация на GitHub Pages

Сборка использует относительные пути (`base: './'` в `vite.config.ts`), поэтому сайт работает
при любом названии репозитория. Публикация настроена через GitHub Actions
(файл `.github/workflows/deploy.yml`) — после настройки сайт обновляется сам при каждом `git push`.

### Шаг 1. Создайте репозиторий и отправьте код

1. На github.com нажмите **New repository**, назовите его (например, `study-dirt`), **не** добавляйте README/.gitignore. Создайте.
2. В папке проекта выполните (подставьте свои имя пользователя и репозиторий):

   ```bash
   git init
   git add .
   git commit -m "Первый коммит"
   git branch -M main
   git remote add origin https://github.com/ВАШ_ЛОГИН/study-dirt.git
   git push -u origin main
   ```

   Перед `git add .` убедитесь, что `.env` не попадёт в коммит: `git status` не должен его показывать.

### Шаг 2. Добавьте ключи Supabase в секреты репозитория

Файла `.env` на GitHub нет, поэтому ключи передаются сборке через секреты:

1. Репозиторий → **Settings** → **Secrets and variables** → **Actions** → **New repository secret**.
2. Создайте два секрета (имена — ровно такие):
   - `VITE_SUPABASE_URL` — ваш Project URL;
   - `VITE_SUPABASE_ANON_KEY` — ваш anon public ключ.

### Шаг 3. Включите GitHub Pages

1. Репозиторий → **Settings** → **Pages**.
2. В разделе **Build and deployment** → **Source** выберите **GitHub Actions**.

### Шаг 4. Запустите публикацию

Публикация стартует при каждом пуше в ветку `main`. Если пуш уже был, запустите вручную:
вкладка **Actions** → **Deploy to GitHub Pages** → **Run workflow**.

Через 1–2 минуты сайт будет доступен по адресу:

```
https://ВАШ_ЛОГИН.github.io/НАЗВАНИЕ_РЕПОЗИТОРИЯ/
```

Отправьте эту ссылку одногруппникам — больше ничего настраивать не нужно.

### Альтернатива: вручную, без Actions

Если Actions не нужны: выполните `npm run build` (ключи возьмутся из локального `.env`),
затем опубликуйте содержимое `dist/` в ветку `gh-pages`, например командой
`npx gh-pages -d dist`, и в **Settings → Pages** выберите **Deploy from a branch → gh-pages**.

## 9. Как это работает

### Ник вместо регистрации

При нажатии **«Войти»** вы вводите ник — он сохраняется в `localStorage` браузера, и при следующем
визите вводить его не нужно. Сменить имя или выйти можно в меню профиля (нажмите на свой ник в шапке).
Если нажать «Я выполнил» или «СДЕЛАТЬ ГРЯЗЬ», не войдя, сайт сам попросит ник.

Ники сравниваются **без учёта регистра**: `Ivan` и `ivan` — один и тот же человек.

### Алгоритм «Сделать грязь»

1. Берутся все задания всех дисциплин.
2. Отбрасываются те, что текущий пользователь уже выполнил (есть отметка с его ником).
3. Для каждого считается число дней до дедлайна относительно сегодняшней даты.
   Оно может быть отрицательным: `-5 дней` — дедлайн был 5 дней назад, `0 дней` — сегодня, `1 день` — завтра.
   Слово «просрочено» не используется — всегда показывается именно число.
4. Определяется срочность: задание **срочное**, если осталось **3 дня или меньше** (сюда же попадают сегодняшние и просроченные).
5. Задания раскладываются по четырём группам в таком порядке:
   1. 🔴 важное + срочное
   2. 🟡 важное + не срочное
   3. 🟢 неважное + срочное
   4. ⚪ неважное + не срочное
6. Внутри каждой группы задания сортируются по числу дней по возрастанию: `-5`, `-1`, `0`, `1`, `3` — чем меньше осталось, тем выше.
7. Просроченные задания подсвечиваются красным.

Клик по заданию в «грязи» открывает его подробности — там же можно нажать «Я выполнил», и задание исчезнет из списка.

### Нумерация заданий

Номер задания — это его позиция внутри дисциплины (1, 2, 3…). Он не вводится вручную.
После удаления задания или перестановки стрелками ↑ ↓ номера пересчитываются без пропусков:
удалили №2 — бывшее №3 становится №2.

### Обновление данных

После любого действия (создание, изменение, удаление, отметка) данные перезагружаются из базы автоматически.
Изменения других пользователей подтягиваются, когда вы возвращаетесь на вкладку сайта.

## 10. Настройки и структура кода

**Срочность** настраивается в одном месте — `src/config.ts`:

```ts
export const URGENT_DAYS = 3; // срочное = осталось 3 дня или меньше
```

Там же — названия категорий, подписи типов и важности, порядок и названия групп «грязи».

```
.
├── .github/workflows/deploy.yml   публикация на GitHub Pages
├── supabase/schema.sql            SQL для создания таблиц
├── src/
│   ├── main.tsx                   точка входа
│   ├── App.tsx                    состояние, загрузка данных, действия
│   ├── config.ts                  все настройки (URGENT_DAYS и др.)
│   ├── types.ts                   типы данных
│   ├── hooks.ts                   хранение ника в браузере
│   ├── styles.css                 стили (в т.ч. мобильная версия)
│   ├── components/
│   │   ├── Header.tsx             шапка, вход, кнопка «Сделать грязь»
│   │   ├── LoginModal.tsx         окно ввода ника
│   │   ├── Category.tsx           категория
│   │   ├── Subject.tsx            дисциплина
│   │   ├── Task.tsx               строка задания
│   │   ├── TaskModal.tsx          форма создания/редактирования задания
│   │   ├── TaskDetails.tsx        подробности задания, «Я выполнил»
│   │   ├── SubjectModal.tsx       создание/переименование дисциплины
│   │   ├── DirtyList.tsx          результат «Сделать грязь»
│   │   ├── ConfirmDialog.tsx      подтверждение удаления
│   │   ├── Modal.tsx              базовое модальное окно
│   │   └── Toast.tsx              уведомления об ошибках
│   ├── services/
│   │   ├── supabaseClient.ts      подключение к Supabase
│   │   └── database.ts            все запросы к базе
│   └── utils/

```

## 11. Безопасность

- В браузере (и в собранном `dist/`) всегда виден anon-ключ Supabase — так устроен любой сайт на Supabase. Это нормально, он предназначен для публичного использования. **Секретный `service_role` ключ нигде не используйте.**
- `.env` в `.gitignore`; в GitHub попадают только пустые значения из `.env.example`. Для сборки на GitHub ключи лежат в **Secrets** репозитория.
- Поскольку входа по паролю нет, политики доступа в `schema.sql` разрешают чтение и запись всем, у кого есть ссылка на сайт. Любой посетитель может изменить или удалить данные, и ник ничем не защищён — можно назваться чужим. Для закрытой группы одногруппников этого достаточно; не публикуйте ссылку широко.

## 12. Частые проблемы

| Проблема | Решение |
|---|---|
| Сайт пишет «не подключено к базе данных» | Нет `.env` или он пустой. Заполните и перезапустите `npm run dev`. На GitHub — проверьте секреты `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY` и перезапустите Actions. |
| «Не удалось загрузить данные» | Не выполнен `schema.sql`, неверный URL/ключ, или проект Supabase на паузе (бесплатные проекты засыпают после недели без запросов — нажмите **Restore** в панели Supabase). Подробности — в консоли браузера (F12). |
| Пустая страница на GitHub Pages | В **Settings → Pages → Source** должно стоять **GitHub Actions**; проверьте вкладку **Actions** на ошибки. |
| `npm run build` падает с ошибкой типов | Прочитайте сообщение — оно указывает файл и строку. |
